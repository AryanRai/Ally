# Question history and shared input

Phone and watch render device questions and approvals inside the conversation timeline. A stable server creation time, or a persisted first-received time for older requests, places each request among message timestamps. Resolved requests stay in that position as later messages arrive. They show Question or Approval instead of a pending-action heading, preserve the question text, and show an available confirmed answer with option labels. Secret fields are masked. Only pending requests trigger the question auto-scroll. Ordinary history navigation and unread visibility guards remain intact.

Shared phone text, images and files use the existing mid-turn input routes. Queue retains new images for the continuation in the same session; Steer delivers text and new local image inputs through the supported Codex desktop/app-server protocol. File references are described as user-provided data. The original turn's images are not replayed with queued input. Unsupported steering remains explicit and retains the draft. External Codex Queue continues through the existing idle-waiting message route.

Retries bind the exact request ID, mode, text and attachments. Uploaded assets are reused and drafts clear only after acknowledgement. The phone verifies the desktop `inputAttachments` capability before submitting an attachment follow-up, protecting shared files during a rolling update to an older server. This capability is advertised by authenticated `/v1/status`.
