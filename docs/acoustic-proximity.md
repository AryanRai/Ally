# Experimental audio-assisted proximity

User explicitly clarified on27October2026 that audio is intended for proximity, not merely a confirmation sound. This increment supplements the existing authenticated BLE approach and explicit swipe. It does not implement acoustic time-of-flight, centimetre distance, room presence authentication, or universal reliable ranging.

## Hardware evidence

Read-only Pixel7 `pm list features` reports Bluetooth LE, audio low latency/pro and Wi-Fi RTT. Windows `netsh wlan show wirelesscapabilities` reports Wi-Fi Direct roles supported and **FTM as Initiator: Not Supported**. A compatible Windows responder/phone-peer ranging path is not established. No Wi-Fi scanning, SSID collection, security changes or fake Wi-Fi distance has been added. Same-network reachability can transport authenticated commands but does not prove near distance.

[Android RTT](https://developer.android.com/reference/android/net/wifi/rtt/package-summary) requires supporting APs/peers. Research such as [BeepBeep](https://www.microsoft.com/en-us/research/publication/beepbeep-a-high-accuracy-acoustic-ranging-system-using-cots-mobile-devices/) demonstrates acoustic ranging with dedicated timing algorithms; those results are not performance claims for this phone/laptop. A single audible chirp plus network timestamps does not remove audio/network latency. Actual two-way ranging would require a separate PC microphone implementation, consent and hardware validation; none is claimed here.

## Opt-in flow

Phone Hold-close settings → **Experimental audio proximity**. The feature is off by default. Enable / Resume starts a visible microphone foreground service after normal Android permission decisions. The saved on/off preference has no elapsed timeout. Notifications must be enabled for the ongoing visible Stop control; notification Stop and settings Stop both disable the preference. Existing voice permission alone never starts it. Lock/disconnect cancel the current check without destroying this already user-started service; checks wait for unlock and the authenticated paired connection. Android process termination, force-stop, reboot or an APK update can require a visible Resume; saved preference and calibration survive. No background microphone-service restart or permission bypass is attempted. See [Android's microphone foreground-start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).

Collect3FAR and3NEAR chirp checks at least12seconds apart with the same PC volume, audio output and phone orientation. The PC emits a brief audible randomized eight-symbol tone sequence through its normal default audio output. During each check the phone acquires at most4.2seconds of mono16kHz PCM, stops recording before analysis, verifies the fresh frequency sequence locally, and calculates a matched-tone level. PCM and analysis copies are zeroed/discarded; no captured audio file, network upload, transcript or model input is created. The PC's temporary WAV contains only generated synthetic tones and is removed after playback.

Calibration requires all three near levels to exceed all three far levels by at least6dB. This is a conservative acoustic-level classifier, affected by orientation, speaker/microphone processing, reflections and ambient noise. It is not a distance measurement. Calibration values persist, but the microphone session and fresh confirmation do not.

Enable **Audio proximity · on until stopped** to require matched acoustic confirmation before a review card. Fresh authenticated coarse BLE presence must remain stable for1.5seconds before a check, with12seconds between attempts. Two automatic attempts are allowed per visit; further attempts require a4dB change in the rolling radio median. Radio loss of1.5seconds resets the visit budget, but never rearms a consumed offer. The settings page also offers an explicit Check proximity now action. The strict radio-only approach is not required for audio checking. Only a verified level above the saved threshold offers the card after the silent hold. NEAR evidence lasts15seconds to cover the3second hold,8second swipe offer and bounded PC receipt; fresh radio remains required throughout. Missing/unverified/stale audio blocks review. A completed/expired offer requires a fresh verified FAR chirp before another offer. The user must still swipe to open local review and explicitly Send or Continue afterward. No automatic media playback, capture/upload, chat send or agent work is authorized by a chirp.

Phone lock, connection loss, user Stop and voice recording cancel checks. The PC rejects probes without an explicitly enabled authenticated phone connection, from watches, while locked, during its8second safety cooldown, or with a previously attempted request ID. Disconnect/lock revoke grants; only the existing explicitly started phone service renews the opt-in before an eligible bounded probe. The current phone is compatible with the older finite PC grant because it renews before each check. Fresh random tone symbols travel only through the authenticated socket. Public tones are convenience evidence, never pairing credentials or authentication. Audio routing remains separate.
