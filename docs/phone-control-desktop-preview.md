# Phone control desktop preview

Phone control continues to exclude Ally itself, settings/permission prompts, credentials, payments, communications and protected controls. A request made while the phone is displaying Ally therefore cannot inspect its screen. Its diagnostic now explicitly says to press Home manually and inspect again; no security gate or transport fallback is relaxed. Own-app widget nodes remain protected too. Do not retry a failed input or drag without checking the action receipt and current state.

For a user working at a computer, the phone_control tool now advertises the optional desktopPreview:true argument. The tool instruction now says to include it in the FIRST call when the user explicitly identifies a laptop/desktop origin; omit for phone/watch origin, and offer the choice for unknown origin. This is not automatic guessing based on Wi-Fi or chat identity. Omit it for phone/watch use, unknown origin, or when unwanted. Existing phone control executes first; failed/refused control never opens a viewer. Successful opted-in control requests the existing phone_viewer_start integration, with its separate real raw-view approval and exact phone/authorized ADB identity checks. It requires an installed configured local scrcpy executable. No automatic installation, pairing, security-setting change or alternative viewer fallback is performed.

The viewer is read-only with no audio/input/clipboard synchronization/recording; frames stay in the local window, not the agent. Raw screen contents can be sensitive and the existing viewer approval says so. A consent denial leaves control unchanged. The viewer binds to the actual approved control grant, not model-supplied times: control End, phone Stop/revoke, expiry, disconnect or shutdown aborts its lifetime. Cancellation while awaiting viewing consent cancels the request. Returning from the MCP call does not end the approved control session or viewer prematurely. Existing viewer Close/Stop remains available.

A protected-screen error cannot be recovered by requesting this raw viewer. No origin-specific preview is enabled silently. The existing authenticated MCP registration publishes this schema after a normal validated, guarded Ally desktop activation. Until activated the running desktop still serves the old tool.
