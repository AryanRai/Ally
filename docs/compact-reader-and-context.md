# Compact reader, context controls and responsiveness

The existing collapsed reply card keeps its max-h-48 reading area. At its top edge, 120 pixels of deliberate additional upward scrolling moves to the previous assistant reply; at the bottom of an earlier reply, downward overscroll moves forward. A 650ms gesture cooldown prevents trackpad momentum skipping many replies. Small Older/Newer arrows and Alt+Up/Down offer alternatives. Only the selected reply is rendered. Live activity remains indicated while reading earlier output, and Follow latest returns to the current response. There is no new history cap. All user messages, decisions and complete history remain available inside More controls; the separate always-visible Recent messages row is removed.

Selection/drawing, Screen, Clipboard and Agents share one wrapping control row in the same pill style. Detailed drawing controls, clipboard contents and agent rows are opt-in disclosures. Closed clipboard/history/agent content adds no separate rows. Existing reply presentation, card height, main composer and animations are retained. Short manually sized windows still scroll.

Screen auto-attach is explicit, off by default and persists across chats. Enabling it does not capture. A nonempty submitted question requests one fresh finite OS capture after briefly hiding Ally, then uses the existing image-send path. There is no recording or background capture loop. The exact selected chat is rechecked after awaiting capture; a chat change aborts delivery. Busy chats retain the question/draft until image submission is possible. An explicitly attached Circle selection takes priority; an existing drawing retains its context and shows a compact note to clear it for a fresh screen. Capture denial/unavailability sends text normally with an honest compact indication and never substitutes an earlier screen. Voice uses the same submission path; no-speech causes no capture. Active selection/drawing windows block fresh capture to prevent capturing Ally's overlay. Phone/watch behaviour and OS security settings are unchanged.

Responsiveness investigation found repeated long-transcript work: useChats recreated the active message array on every parent update; collapsed mode sorted the full interaction timeline even when not displayed; unchanged interaction polls replaced state; native history reconciliation repeatedly scanned/normalized earlier messages and copied repeated-message buckets. Stable snapshots and memoized/lazy timelines avoid unrelated work, unchanged polls retain identity, and reconciliation uses indexed ordered matching, preserving repeated prompts, usage and interrupted output. Drawing geometry updates now send only window bounds, rather than cloning every diagram/sketch and sending the full board to both renderers on each movement. These are concrete stall reductions. Runtime logs also contain native Codex thread/list timeouts; this work does not establish that every intermittent hang shares one cause, or claim measured live frame-time improvement.
