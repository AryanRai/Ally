# Live device replies and folder refresh

Phone and watch now display `liveText` from the authenticated turn endpoint while the agent runs. Existing foreground polling updates the phone every two seconds and the watch every 1.5 seconds, plus request latency. The watch opens its reply page when text first arrives; subsequent chunks do not force the reader back to the bottom. Completed watch answers open at the start of the latest assistant message rather than skipping to the end of a long answer. Phone follows the tail only while the reader is near it. Voice controls retain their fixed layout.

The phone previously discarded every `components` field and displayed only the introduction. Both Android clients now use the same reply/card parser. The phone displays all six supported card sections, Markdown links, checklists, progress, tap-to-start local countdowns and explicitly tapped suggested follow-ups. The user's research answer was verified through read-only history to contain six cards (572–711 characters each); none was truncated by the backend. The defect was in phone presentation. Partial card titles/bodies/checklists also appear as readable live text; executable card controls are created only after completion.

The bridge decodes plain progress commentary and partial JSON reply/card text, including split escapes and Unicode. Incomplete cards are never interactive. Preview text is bounded to 12,000 characters and source accumulation to 64,001; oversized structured output falls back to readable text. Continuations start a fresh preview. Partial text survives a turn error/Stop in the current device view, and a final reply stays visible even if native history has not caught up. Private thinking events are not exposed.

Both clients retry only the GET for the accepted turn after transport or transient gateway failures, with backoff from 1.5 to 30 seconds. They keep readable partial text and show Reconnecting. Authentication, expired turns, invalid responses, TLS errors and cancellation are not automatically retried. Message submissions, input, approvals and Stop retain their existing explicit delivery behavior.

Before starting a turn, the bridge reloads the selected native session's folder without acquiring a writer, preserving the exact session ID and permission. It does not recreate deleted projects or substitute unrelated folders. If the current native folder is genuinely unavailable, the error explains how to correct the original chat on desktop. The reported screenshot belonged to Claude session `60ce8fdb-d410-4e20-8e53-6a80107d3625`: its old scratch folder had been removed and its latest recorded folder is the existing Ally repository. Claude's concurrent latest-cwd reader fix remains in its owned, uncommitted sessions files; the deployed build includes it, but this change does not commit those files.
