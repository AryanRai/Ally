# Prompt control sessions and notch follow-ups

Phone control defaults to a prompt-scoped grant when the authenticated caller has one exact Ally-managed active run. A run-owned AbortController is created by trackRunningSession and aborted by finishRunningSession on normal completion, stop or error. The model cannot supply a run ID or extend a completed prompt. Ambiguous/unknown owners have no prompt lifetime; automatic calls use the existing explicitly labelled15-minute timed approval. Explicit sessionScope:prompt without an exact lifetime fails before screen access.

One real approval covers repeated finite plans within that prompt. The prompt grant has a60-minute safety cap; it ends earlier with its prompt, phone Stop/revoke, disconnect or explicit End. The read-only desktop preview binds to that same grant, retaining its separate viewing consent. Explicit sessionMinutes from1–60, or sessionScope:timed, selects the existing timed session and can span prompts. Switching grant scopes asks again instead of silently enlarging an approval. Plans remain bounded to8operations/60seconds with fresh revisions, partial delivery receipts and no automatic replay. The phone's existing grant validation remains unchanged; the backend ends the grant on the actual prompt completion event.

The expanded desktop notch now offers Queue and Steer now during a running response. Queue is the default and waits behind the response; Steer sends guidance to the current response through the existing authenticated input endpoint. Selection persists per conversation. Delivery mode is part of the request binding and is held fixed while an uncertain send receipt exists so retry does not silently change delivery or duplicate input. Attachments, permission choice and unsent drafts remain intact.

This work does not remove Ally from protected-screen checks, automate Home after a refusal, add a self-control bypass, or alter OS/security approvals. Existing phone tools explicitly exclude Ally itself. Live inspection and widget placement remain subject to that restriction. No separate sanctioned Ally UI test-control interface was found in the available tools; unit/build checks do not prove on-device visuals.
